# Архитектура распределённого нотариального документооборота

## Компоненты

1. **Permissioned Ethereum-compatible blockchain** — private Ethereum/Besu сеть для консорциума ФНП и региональных палат.
2. **Smart contracts** — `NotaryAccessControl`, `DocumentRegistry`, `AuditContract`, `ZKVerifier`.
3. **Backend API** — NestJS REST API с JWT, RBAC guards, audit interceptor, модулями IPFS/blockchain/ZK.
4. **Frontend** — Next.js dashboard для нотариусов, аудиторов, администраторов и публичных проверяющих.
5. **Off-chain storage** — IPFS с предварительным AES-256-GCM шифрованием документа.
6. **ZK module** — Circom circuit доказывает знание секрета владельца и hash документа без раскрытия содержимого.
7. **Audit subsystem** — дублирует бизнес-аудит в API и append-only события on-chain.

## Поток регистрации документа

1. Нотариус проходит wallet-signature authentication.
2. Backend принимает файл, считает hash исходного документа и encrypts документ.
3. Encrypted payload отправляется в IPFS, возвращается CID.
4. Backend готовит metadata commitment, frontend запрашивает wallet signature.
5. `DocumentRegistry.registerDocument` фиксирует `documentHash`, `metadataHash`, `cid`, `timestamp`.
6. `AuditContract.logAction` записывает immutable событие.

## Roadmap разработки

- Этап 1: базовая архитектура, smart contracts, API skeleton, UI skeleton.
- Этап 2: PostgreSQL persistence, Prisma migrations, реальный IPFS adapter.
- Этап 3: Besu IBFT/QBFT network, deployment scripts, role bootstrap.
- Этап 4: production Groth16 verifier generated by SnarkJS and trusted setup automation.
- Этап 5: e2e тесты, load testing, gas reports, security review.
